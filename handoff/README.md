# 交接说明：在你的机器上跑一次"固定规则库"训练

这份文档写给负责在自己机器上跑训练的同学。照着从上往下做即可；每一步都写了怎么算通过、没通过该把什么发回来。

## 1. 这次要跑什么

训练一个 4B 的小模型，让它学会在多智能体任务里做"调度员"。每条轨迹的奖励一半是任务完成度（程序判），一半是安全分（由 OpenAI 的一个模型按 20 条规则打分）。这次跑的是**规则固定不变**的一组：一共 28 步参数更新，在第 0、7、14、21、28 步各做一次测试。

我们要的是测试结果和打分记录，不是模型本身。

整套东西分三部分：

| 部分 | 在哪 | 内容 |
|---|---|---|
| 镜像 | `docker.io/yujun0017/verifierscientist-train:2026-11-11` | 运行环境、基础模型、软件工程类任务用到的 30 个代码库及其环境。下载约 24 GB，解开约 50 GB |
| 这个 Git 仓库 | 你已经克隆的这个 | 训练代码、题库、配置、那 20 条规则、运行脚本、本文档。约 0.6 GB |
| 输出目录 | 你机器上自己选的一个目录 | 训练产出、API 账本、密钥文件。运行时挂进容器 |

容器启动时会把仓库里 `tree/` 下的内容铺到镜像内的固定路径上。以后如果我们改了代码，你只需要 `git pull`，不用重新拉镜像。

## 2. 机器要满足的条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 显卡 | 同一台机器上 4 张 A100 或 H100，训练期间独占 | 代码只认这两种型号，且必须正好 4 张。3 张训练，1 张跑被调度的模型 |
| 显存 | 我们只在 80 GB 的卡上跑过 | 40 GB 的卡可能不够。第 1 步会打印显存，请把数字告诉我们 |
| 显卡驱动 | 580 或更新 | 环境是按 CUDA 13 编的（PyTorch 2.11）。驱动更老的话跑不了，第 1 步会直接报出来 |
| Docker | 能用 `--gpus`（装了 NVIDIA Container Toolkit） | |
| 磁盘 | 镜像解开约 50 GB；输出目录至少 350 GB | 每个模型存档约 51 GB，程序会保留第 7/14/21/28 步和最近 2 个 |
| CPU | 我们用的是 16 核 | 内存下限没有单独测过 |
| 网络 | 容器内能访问 `https://api.openai.com` | 可以走代理：运行前设好 `HTTPS_PROXY` 环境变量，脚本会传进容器 |
| 时间 | 冒烟测试约 2 小时；正式训练约 40–45 小时，中途不能断 | 我们这里每步更新约 1.3 小时，每次测试约 0.6 小时 |

API 花费由程序强制封顶在 25 美元，预计实际 10–15 美元。密钥由项目负责人单独给你。

这个 GitHub 仓库是私有的，需要项目负责人把你加为协作者。镜像是公开的，直接拉取即可，不需要 Docker Hub 账号。

## 3. 准备

```bash
git clone git@github.com:YujunZhou/VerifierScientist.git
cd VerifierScientist

docker pull docker.io/yujun0017/verifierscientist-train:2026-11-11

export OUT=/你的/大磁盘/vs_frozen28_out      # 至少 350 GB 可用
mkdir -p "$OUT"

# 密钥文件：一行，等号两边不要空格。不要提交到任何仓库。
echo 'OPENAI_API_KEY=项目负责人给你的密钥' > "$OUT/openai.env"
chmod 600 "$OUT/openai.env"
```

如果要用的不是 0–3 号卡，运行前设 `export GPUS=4,5,6,7`（主机上的卡号）。

## 4. 按顺序做七步检查

每一步都是同一个命令，只换最后一个词：

```bash
./handoff/run.sh <步骤名>
```

前五步是检查，很快，基本不花钱。**任何一步没通过就停下来**，把屏幕输出发给我们，不要跳过。

| 顺序 | 步骤名 | 检查什么 | 用显卡 | 花钱 | 大约多久 | 通过的标志 |
|---|---|---|---|---|---|---|
| 1 | `gpucheck` | 显卡型号、数量、显存、驱动，每张卡做一次小计算 | 是 | 否 | 1 分钟 | 最后一行 `GPUCHECK PASSED` |
| 2 | `envcheck` | 关键软件能导入、git 和编译器在、188 个单元测试 | 否 | 否 | 2 分钟 | `ENVCHECK PASSED` |
| 3 | `verify` | 约 4 万个文件和我们审核过的版本逐一比对 | 否 | 否 | 3–5 分钟 | `VERIFY PASSED` |
| 4 | `netcheck` | 用你的密钥向 OpenAI 发一次极小的请求 | 否 | 不到 1 美分 | 10 秒 | `NETCHECK PASSED` |
| 5 | `workercheck` | 在第 4 张卡上启动本地推理服务，问一句话，再关掉 | 是 | 否 | 3–10 分钟 | `WORKERCHECK PASSED` |
| 6 | `smoke` | 完整流程的缩小版：一次基线测试加 1 步参数更新 | 是 | 约 0.5 美元 | 约 2 小时 | 正常退出，`$OUT/smoke_run/complete.json` 存在 |
| 7 | `train` | 正式训练，28 步 | 是 | 10–15 美元 | 40–45 小时 | `$OUT/run/complete.json` 存在，里面 `full_28_step_experiment_complete` 为 `true` |

几点说明：

- 第 2 步里有 2 个测试是为我们原来的集群调度写的，在这里导入不了，脚本已把它们算作预期内，不影响通过。
- 第 4 步如果报连接错误，说明容器里访问不到 OpenAI。请把完整报错发给我们；如果你们有代理，设好 `HTTPS_PROXY` 再试。
- 第 5 步第一次启动要现场编译一些显卡内核，会慢一些。失败时脚本会打印服务日志的最后 60 行，请一并发回。
- **第 5、6 两步是最可能出问题的地方**：这套环境在这个镜像里还没有在显卡上实际跑过（我们这边打包的机器没有显卡可用），只验证了不用显卡的部分。
- 第 6 步通过后，请先运行 `./handoff/run.sh pack` 把结果包发给我们看一眼，再开始第 7 步。

## 5. 正式训练

训练要连续跑将近两天，请放在 `tmux`、`screen` 里，或者这样放后台：

```bash
nohup ./handoff/run.sh train > "$OUT/train_console.log" 2>&1 &
```

随时查看进度（只读，不影响训练），在主机上直接运行：

```bash
python3 handoff/checks/status.py "$OUT"
```

它会列出各阶段是否完成、已花的 API 费用、最新日志的最后几行。阶段顺序是：`test_00`、`train_01_smoke`、`train_07`、`test_07`、`train_14`、`test_14`、`train_21`、`test_21`、`train_28`、`test_28`。

**如果中途断了**（机器重启、被抢占、报错退出）：

- 不要删除 `$OUT` 里的任何东西，也不要直接重新运行 `train`。程序为了防止覆盖已有存档，会拒绝在同一个目录里从头再来。
- 运行 `./handoff/run.sh pack`，把生成的结果包和 `train_console.log` 发给我们。从最近一个里程碑续跑需要我们这边生成一份续跑配置，推到仓库后你 `git pull` 再继续。

## 6. 跑完之后发回什么

```bash
./handoff/run.sh pack
```

它在 `$OUT` 下生成一个 `results_日期_时间.tgz`，通常几百 MB 以内，包含日志、全部轨迹、打分记录、测试指标和 API 账本。**不包含**模型存档、请求缓存和密钥文件。把这个文件发给我们即可。

模型存档（`$OUT/run/milestones/` 和 `$OUT/run/checkpoints/`，每个约 51 GB）请先留在本地，等我们确认结果后再决定删除还是传回。

## 7. 注意事项

- **不要改 `tree/` 下的任何文件。** 程序启动前会核对每个文件的指纹，改动一个字节都会拒绝启动。需要改代码时告诉我们，由我们改完、重新生成校验清单再推到仓库。
- **同一时间只跑一个步骤。** 两个训练进程同时用这四张卡或同一个输出目录会互相破坏。
- **密钥只放在 `$OUT/openai.env`。** 不要写进命令行、脚本或仓库。`pack` 不会把它打进结果包。
- **这个仓库是未公开的研究材料**（含未发表的代码和带标准答案的题库），请不要转发或公开。镜像是公开的，里面没有这些内容。
- 容器以 root 身份运行，`$OUT` 里的文件属主会是 root。

## 8. 出问题时发回什么

1. 出问题那一步的完整屏幕输出。
2. `./handoff/run.sh pack` 生成的结果包（如果已经有输出）。
3. `nvidia-smi` 的输出和 `docker version` 的输出。

## 附：目录和文件

| 路径 | 内容 |
|---|---|
| `handoff/run.sh` | 在主机上运行的启动脚本，负责拼 `docker run` 命令 |
| `handoff/container_entry.sh` | 在容器里运行的入口，由上面的脚本调用 |
| `handoff/checks/` | 各检查步骤的脚本 |

| `tree/VerifierScientist/experiments/guidance_rl_2026-11-02/frozen28_2026-11-11/` | 这次运行的代码（`code_v4/`）、正式配置和冒烟配置及其校验清单 |
| `docker/` | 镜像是怎么做出来的（只供查阅，你不需要重做） |

可用的环境变量（都在运行 `run.sh` 之前设置）：

| 变量 | 作用 | 默认 |
|---|---|---|
| `OUT` | 输出目录，必填 | 无 |
| `GPUS` | 使用主机上的哪四张卡 | `0,1,2,3` |
| `IMAGE` | 镜像名 | `docker.io/yujun0017/verifierscientist-train:2026-11-11` |

| `HTTPS_PROXY` 等 | 代理设置，原样传进容器 | 不设 |
